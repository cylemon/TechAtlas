# 规格文档

TechAtlas 的产品规格。**这些文档是实现的唯一真源**——代码与文档冲突时，先确认哪个是对的，再改另一个。

| 编号 | 文档 | 状态 | 内容 |
|---|---|---|---|
| 01 | [话题边界](01-topic-boundary.md) | 已定稿 | 判定 Agent 接收什么样的课题 |
| 02 | [需求规格](02-requirements.md) | 已定稿 v10 | 定位、会话、守卫、知识库与图谱缓存、检索流程、最新动态、信息源、跨话题碰撞 |

02 的决策记录见其 §6：**D-01～D-24 全部收敛**（D-20、D-21 已作废），**无待决项**。

读 02 时优先看三处：

- **§1.1 首要价值**——「了解技术领域的最新发展动态」是产品的立身之本。它一路决定了：采集（FR-SRC）为何是 P0、图谱保鲜期为何是 15 天、新知识为何走**通知栏**而不走图谱重生成（D-19）。
- **§3.5 知识库与图谱缓存**——两个存储必须分开。知识库只存外部来源的知识，LLM 生成的图谱进图谱缓存。混淆会让 LLM 输出污染知识库的语义检索。
- **§3.5.4 知识库的时间模型**——知识有 1 年硬删除期，依据是「LLM 会持续吸收新知识，今天的补充终将成为明天的冗余」。这条把知识库从一个只增不减的档案，变成了**一个有限期的补充层**。

§3.9 的 FR-SYNTH（跨话题碰撞）本期不实现，但要求架构留位——留位的核心是**把「话题来源」抽象为一等概念**，让下钻与碰撞共用一套机制。

## 阅读顺序

新加入的人按 01 → 02 读。01 更短且已定稿，它定义的边界是 02 中守卫模块（FR-GUARD）的输入。

## 规约

- **待决策的问题写进文档，不留在对话里。** 02 的 §6 就是为此存在的——口头的"待定"会在实现阶段变成随机的技术选择。
- **记录被否决的方案及理由。** 例如 01 §1「为什么不用学科清单」——否则同一个错误方案会被反复提出。
- **决策性的经验数据直接写进文档。** 如「不同领域会衍生出 18 个互不重叠的关系词」这类实测结论，是后续判断的依据。
